### 2.4 当前用户体验现状与风险

项目已经具备较好的基础：正文行高约 1.75–1.8、文章宽度受控、核心表格有横向滚动、文章有面包屑和相关文章、中文计算器结果区使用了 `aria-live`。这些能力应保留，不需要为“重新设计”而推翻现有视觉体系。

本次代码审阅仍发现以下需要验证或补齐的点：

- 主模板和文章模板尚未发现明确的“跳到主要内容”链接，键盘用户可能需要重复经过整组导航。
- 多处导航采用水平滚动解决移动端空间不足，但需要确认用户能看出“还可以横向滑动”，且焦点进入后不会被裁切。
- 普通页面的 Breadcrumb 结构目前主要是“首页 → 当前页”；专题页理想层级应为“首页 → 专题 → 当前专题”，可见导航与结构化数据必须一致。
- 文章表格虽然可以横向滚动，但需要确认存在可理解的滚动提示、表头语义、`caption` 或邻近说明，不能只做到“不溢出”。
- 英文计算器输入无效时直接隐藏结果，没有可读的错误信息；结果容器也需要确认动态更新能被辅助技术感知。
- 中英文计算器功能不对等：英文有收益率、DRIP 和收入目标三类计算，中文只有基础收益率和收入计算，需判断是产品差异还是遗漏。
- 外部 Google Fonts 仍可能影响首屏字体加载；文章主图使用单一尺寸的概率较高，需要核对响应式图片、LCP 与带宽消耗。
- 长专题扩写后，如果只增加段落，会降低扫读效率；必须同步加入摘要、目录、分段标题、表格说明和明确的下一步动作。
- 核心互动、链接和按钮需验证键盘焦点、颜色对比、44×44 CSS 像素触控区域和相邻控件至少 8px 间距。

今天的 UX 目标不是增加装饰，而是让用户更快完成“理解概念 → 核对风险 → 查看数据 → 使用工具 → 继续研究”的任务路径。

## 五、P0-2：英文专题 Hub 金融事实审计

### 5.1 审计对象

- `src/pages/topics/dividend-investing-basics.astro`
- `src/pages/topics/dividend-stock-screening.astro`
- `src/pages/topics/high-yield-dividend-stocks.astro`
- `src/pages/topics/dividend-etf-history.astro`

### 5.2 审计原则

每个金融结论必须属于以下三类之一：

1. 有权威来源支持的事实；
2. 有明确前提、仅作说明的经验规则；
3. 需要删除或改写的无依据绝对判断。

不得把经验范围包装成行业统一标准，不得把税务结果写成对所有投资者都适用的结论。

### 5.3 逐项检查

#### A. 税务与分配性质

检查：

- qualified dividend 的持有期说明是否准确；
- REIT、BDC、MLP、外国股票是否被错误合并为同一种税务性质；
- ROC 是否明确为成本基础调整，而不是“免税收益”；
- Section 1256 是否明确基金层面、投资者层面和最终税表之间的边界；
- 税率是否标明年份、申报身份和仅供示例；
- 是否提醒以基金年度税务文件和个人税务顾问为准。

达到效果：用户不会把简化说明误当作个人税务结论。

#### B. 收益率与安全性指标

检查：

- “2–6%”“低于 70%”“高于 1.2×”等范围是否标记为普通公司启发式指标；
- REIT 应使用 AFFO、BDC 应结合 NII、MLP 应结合 DCF，不能套普通公司 payout ratio；
- covered-call ETF 的 distribution rate、SEC yield、income yield 和 total return 是否区分；
- 高收益率是否与价格下跌、ROC、NAV 侵蚀、杠杆和期权上行受限同时解释。

达到效果：页面能帮助用户识别风险，而不是提供机械筛选阈值。

#### C. 投资行为措辞

检查并弱化以下绝对表达：

- “always reinvest”；
- “best purchases usually happen”；
- “pick 5–10 stocks”；
- “hold 20–40 names”；
- “safer than”；
- “should use”；
- “best in tax-advantaged accounts”。

改为条件表达，例如：

- “可能适用于处于积累阶段且不需要现金流的投资者”；
- “需要结合账户类型、税率、时间跨度和流动性需求”；
- “示例不是统一的持仓数量建议”。

达到效果：保持教育属性，避免页面被理解为个性化投资建议。

#### D. 数字、示例与来源

检查：

- 所有金额、收益率、税率、年份和持有期是否可复算；
- 示例是否区分本金、追加投入、分红和价格增长；
- 数据是否有 `dataAsOf` 或正文更新时间；
- 发行商、SEC、IRS 等一手来源是否优先；
- 第三方数据只用于交叉验证，不替代发行商定义。

达到效果：数字具有复核路径，未来更新时能明确知道改哪里。

## 八、P1-3：用户体验、可访问性与性能审计

### 8.1 审计范围

至少覆盖以下页面类型，英文与中文各抽样一页：

- 首页：`/`、`/zh/`；
- 文章列表：`/articles/`、`/zh/articles/`；
- 长文章：新手股息文章英文版和中文版；
- 专题 Hub：高股息专题英文版及待扩写中文版；
- 数据表：`/stocks/`、`/zh/stocks/` 或股息日历；
- 工具：`/calculator/`、`/zh/calculator/`；
- 异常路径：英文与中文 404 页面。

### 8.2 信息架构与任务路径

逐页回答四个问题：

1. 用户进入页面后 5 秒内能否知道页面解决什么问题？
2. 第一屏是否出现清晰答案或任务入口，而不是先看到大段背景文字？
3. 看完当前内容后是否只有 1 个主要下一步，以及最多 1–2 个次要选择？
4. 面包屑、导航、正文内链、相关文章和页脚是否表达同一个站点层级？

具体动作：

- 专题页使用“首页 → 专题 → 当前专题”的可见 Breadcrumb，并让 JSON-LD 使用相同层级。
- 长文章在开头加入 3–5 条“快速结论”，超过约 1,500 字时评估加入页内目录。
- 目录使用真实锚点链接，标题层级必须按 `h1 → h2 → h3` 连续，不为了视觉大小跳级。
- 每个专题页设定一个主要任务，例如“按框架筛选股票”；相关链接按学习顺序组织，而不是堆砌关键词。
- 相关文章数量保持克制，优先相关性，不用大量内部链接稀释正文阅读。
- 任何为 SEO 增加的段落，都必须回答一个真实用户问题；不以字数作为验收目标。

达到效果：搜索用户无需返回搜索结果页即可找到解释、风险、数据和下一步工具。

### 8.3 移动端与响应式布局

在 360、390、768 和 1280 CSS 像素宽度抽查：

- 页面不得出现整页横向滚动；只有表格或明确的内容容器可以局部横向滚动。
- 导航横向滚动时保留当前项可见，并提供边缘渐隐或简短提示，让用户知道还有内容。
- 所有按钮、语言切换和主要导航触控区域不小于 44×44 CSS 像素；相邻触控目标至少 8px 间隔。
- 固定或吸顶区域不得遮挡标题、锚点定位内容、键盘焦点或浏览器缩放后的正文。
- 数据表使用横向滚动或移动卡片布局；不通过缩小到难以阅读的字体来塞进屏幕。
- 表格容器增加可见的“左右滑动查看更多”提示，仅在确实溢出时出现。
- 文章图片使用正确宽高比、明确 `width`/`height`，并评估 Astro 响应式图片或 `<picture>`；不让移动端下载不必要的大图。

达到效果：手机用户无需缩放或猜测操作方式即可读完内容、比较数据并完成计算。

### 8.4 键盘与可访问性

仅使用键盘完成：首页导航 → 文章 → 相关文章 → 计算器输入与计算。检查：

- 页面首个可操作项提供“跳到主要内容”链接，获得焦点时可见。
- 所有链接、按钮、`summary` 和输入框有清晰的 `:focus-visible` 状态，不能只依赖颜色变化。
- 焦点顺序与视觉顺序一致；横向滚动导航中的焦点项必须保持可见。
- 正文与背景对比度至少 4.5:1；大字号文本至少 3:1；链接不能只靠颜色与正文区分。
- 图标链接有可访问名称，装饰图标使用 `aria-hidden="true"`。
- 表格补充 `caption` 或邻近标题，列标题用 `<th scope="col">`，必要时行标题用 `<th scope="row">`。
- 计算器字段保留显式 `<label>`，输入错误显示具体文本，并用 `aria-describedby` 关联；结果变化使用 `aria-live="polite"`。
- 200% 浏览器缩放后，无正文丢失、控件重叠或必须双向滚动。
- 若存在动画或过渡，尊重 `prefers-reduced-motion`；禁止持续、无功能目的的动画。

达到效果：键盘用户、低视力用户和使用屏幕阅读器的用户能够完成与鼠标用户相同的核心任务。

### 8.5 内容可读性与金融决策体验

- 正文行高保持 1.5–1.8；阅读列宽建议控制在约 65–80 个英文字符，中文则以不造成超长横向视线为准。
- 大数字使用千位分隔，百分比保留一致的小数位；同一表格不得混用含义不同但名字相似的收益率。
- 表格前说明“如何读这张表”，表格后说明限制，不让用户只看最高数字做结论。
- 风险提示紧邻相关结论，不把所有限制集中到页脚。
- 来源、数据截至日期、作者、复核方式保持可见，但不压过主要答案。
- “非投资建议”不能替代具体风险解释；每项重要判断都说明适用条件和不适用情形。

达到效果：页面既能扫读，也能深读，降低用户把教育信息误当成个性化建议的概率。

### 8.6 性能与渐进增强

执行桌面端和移动端性能抽样，重点记录 LCP、INP、CLS：

- LCP 目标小于 2.5 秒；INP 小于 200 毫秒；CLS 小于 0.1。
- 核对 Google Fonts 对首屏的影响；优先保持可靠字体回退，避免字体加载造成明显闪烁或布局变化。
- 首屏主图应有尺寸、响应式来源和合理优先级；非首屏图片延迟加载。
- Astro 页面保持静态 HTML 优先，仅给计算器等交互区域加载必要脚本，不为简单内容引入整页水合。
- 关闭 JavaScript 后，正文、导航、语言 URL、表格和核心链接仍然可读可用；计算器需显示明确的功能依赖说明或合理退化。
- 不为了视觉效果新增大型依赖；新增脚本必须说明用户价值、体积和失败时的降级方式。

达到效果：SEO 抓取内容与用户看到的核心内容一致，同时减少低速网络和低性能设备的等待。
