# 顶部 UI 与移动端语言切换修复方案

## 已确认根因

`src/styles/global.css` 在多个 `@media (max-width: 760px)` 规则中将 `.site-nav .nav-language` 与 `.article-topbar-nav .article-language-switcher` 设置为 `display: none`。因此手机样式下语言切换链接被直接隐藏，用户无法点击。即使解除隐藏，导航横向滚动也可能把切换入口推到屏幕外。

## 执行方案

1. 移除移动端隐藏语言切换的规则，确保语言入口始终渲染并可获得焦点。
2. 将语言切换固定为导航操作区的可见控件，设置不小于 44×44 CSS 像素的触控区域和足够间距。
3. 主导航移动端采用“品牌 + 可横向滚动主导航 + 固定语言入口”的结构；语言入口不能随主导航内容一起被裁切。
4. 文章顶部导航同样保留语言入口；必要时隐藏低优先级 CTA，但不能隐藏语言切换。
5. 语言入口继续使用真实中英文 URL，不拦截链接、不新增 JavaScript，确保 SEO 抓取和无 JavaScript 使用一致。
6. 保持现有 www、HTTPS、尾斜杠、canonical、hreflang 和桌面端视觉风格。

## 验收标准

- 360px、390px、768px 宽度下，中英文语言入口均可见、可点击。
- 触控区域至少 44×44 CSS 像素，相邻控件至少 8px 间距。
- 键盘 Tab 可以聚焦语言入口，焦点样式清晰且不被横向滚动容器裁切。
- 点击后进入对应语言的规范 URL，保留尾斜杠，不产生额外重定向。
- 主导航可横向滚动时，语言入口仍保持可见或有稳定的固定位置。
- 桌面端导航、文章顶部导航、canonical/hreflang、构建和 JSON-LD 不回归。
